项目概述

Python Complexity Analyzer 是一个生产就绪的 Python 代码质量分析平台，融合了 AST 静态分析引擎、FastAPI 后端（WebSocket 实时推送）和 React + ECharts 交互式前端，实现了类 SonarQube 的完整代码度量体系。

核心能力涵盖：McCabe 圈复杂度计算、LOC/SLOC 统计、函数重复检测、依赖图谱构建与循环检测、多维度风险评分（0–100），并提供 CLI 工具与 Web UI 两种使用模式，适合嵌入 CI/CD 流水线。

系统架构

系统采用三层架构，各层职责清晰、耦合度低：

CLI (cli/analyze.py)  |  React Frontend (Vite + ECharts)
FastAPI Backend  ·  REST / WebSocket  ·  SQLite Tasks
Analyzer Engine  ·  AST → Metrics → Risk → Report

数据流

  • ① 用户提交项目路径
  • ② API 创建后台任务，返回 task_id
  • ③ Analyzer 遍历 .py 文件，AST 解析
  • ④ WebSocket 推送实时进度（0–100%）
  • ⑤ 完成后返回完整 JSON 分析结果
  • ⑥ 前端渲染图表 / 可导出 HTML 报告

分析流水线阶段

5%  文件收集（尊重 ignore 列表）
10–70%  逐文件 AST 解析
72%  跨文件重复检测（MD5）
78%  风险评分
85%  依赖图构建
92%  Top-N 列表
100%  汇总统计

后端分析引擎

⚙️
core.py — 主编排器
analyze_project() 函数统一调度所有分析子模块，聚合输出完整结构化结果。输出字段包括：project_path、summary、files、dependency_graph、top_complex_functions、long_functions、duplicate_functions。
📏
metrics.py — LOC/SLOC 统计
逐行分类：LOC（总行数）、SLOC（源码行，排除空行和纯注释行）、Blank（空行）、Comment（注释行）。默认忽略目录：venv、.git、__pycache__、node_modules、dist、build 等 14 个。
🔀
complexity.py — McCabe 圈复杂度
自研 _CCVisitor AST 访问器，无需第三方库，完整支持 Python 3.10+ match/case。基础复杂度 = 1，每个决策点 +1。CC ≥ 10 标记为 high（阈值可配置）。
🔍
functions.py — 函数提取 & 重复检测
提取函数/方法元数据（行范围、参数、CC、类型注解），重复检测采用空白归一化 + MD5 哈希，对重构后的副本同样有效。标记维度：is_long（≥50行）、is_high_complexity（CC≥10）、is_many_params（>5参数）。
🕸️
dependencies.py — 依赖图 & 循环检测
AST 解析 import / from X import Y（含相对导入），用 NetworkX 构建有向图，区分标准库、第三方库和项目内部导入。循环检测返回所有环路列表。
⚠️
risk.py — 风险评分算法
四因子加权综合评分（0–100），见下方算法章节。评级：A<20 / B 20–39 / C 40–59 / D 60–79 / F≥80。

McCabe 圈复杂度算法

基于 AST 访问器统计决策点，无外部依赖，完整支持 Python 3.10+ 新语法：

AST 节点 / 语法构造CC 增量说明
if / elif+1条件分支
for / async for / while+1循环
except 处理器+1异常捕获分支
三元表达式 x if c else y+1内联条件
布尔运算符 and/or（N 个操作数）+N−1短路运算
推导式迭代 for x in ...+1列表/集合/字典推导
推导式过滤 if 子句+1推导条件
match 语句每个 case+1Python 3.10+ 模式匹配
基础值： 每个函数起始 CC = 1。高复杂度阈值 HIGH_CC_THRESHOLD 默认为 10（可通过环境变量覆盖）。

风险评分算法

每个模块的风险评分是四个维度的加权综合，归一化至 0–100 区间：

risk_score =
  0.40 × normalize(avg_cc,    lo=0, hi=max(project_max_cc, 10))
+ 0.30 × normalize(loc,        lo=0, hi=max(project_max_loc, 500))
+ 0.20 × (high_cc_functions / total_functions) × 100
+ 0.10 × (duplicate_functions / total_functions) × 100
评级分数范围含义
A< 20低风险，代码质量优秀
B20 – 39中低风险，可接受
C40 – 59中等风险，建议重构
D60 – 79高风险，需优先关注
F≥ 80极高风险，紧急重构

API 接口

REST Endpoints

GET /health 健康检查、Python 版本、建议路径
POST /analyze 提交分析任务 → 返回 {task_id, status}
GET /result/{task_id} 轮询结果（完成时返回完整 JSON）
GET /tasks 列出所有任务
GET /report/{task_id} 下载自包含 HTML 报告
WS /ws/{task_id} WebSocket 实时进度推送

请求/响应模型

class AnalyzeRequest(BaseModel):
    project_path: str
    ignore_dirs: Optional[List[str]] = None  # 校验：不含 ".." "/" "\"

class TaskStatus(BaseModel):
    task_id: str
    status:  Literal["pending", "processing", "completed", "failed"]
    progress: int           # 0–100
    message:  str
    result:   Optional[Dict[str, Any]] = None
    error:    Optional[str] = None

任务持久化 (tasks.py)

  • ✅ ThreadPoolExecutor（工作线程数可配置）
  • ✅ 内存 store + SQLite 双重持久化
  • ✅ WebSocket 订阅（asyncio.Queue）
  • ✅ 任务超时强制终止（默认 300s）

SQLite 表结构：

安全设计

🔒 路径遍历防护

_assert_safe_path() 将分析路径限制在 ALLOWED_BASE_DIR（默认：用户 home 目录），拒绝 .. 等跳出尝试。

🚦 滑动窗口限流

基于 deque 的内存滑动窗口，按 IP 限速（无需 Redis），默认 10 次请求/60s，超出返回 429。

🛡️ XSS 防护

HTML 报告生成器全面转义用户数据，防止分析结果中的恶意代码注入到报告文件。

✅ 输入校验

Pydantic 模型对 ignore_dirs 严格校验，禁止包含 ..、/、\ 等危险字符。
